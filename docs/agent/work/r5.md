# Task R5: Export/Import Hardening (Security)

Date: 2026-11-04  
Status: Complete  
Author: Antigravity / OpenClaude  

---

## 1. Problem Statement

An audit of `AndroidExportManager.kt` revealed critical security, reliability, and architectural issues in the backup/restore pipeline:

1. **Chunk Length Unchecked Allocation (DoS / OOM / NegativeArraySizeException)**:
   In `ChunkedAesInputStream.loadNextChunk()`, the stream reads a 4-byte `len` from the unauthenticated input stream and immediately executes:
   ```kotlin
   val len = ByteBuffer.wrap(lenBuf).int
   val cipherBuf = ByteArray(len)
   ```
   If a crafted or corrupted file specifies a negative `len`, the JVM throws `NegativeArraySizeException`. If `len` is excessively large (e.g. 2 GB), it throws `OutOfMemoryError` or crashes the process. Neither represents the required `SecurityException`. Minimum ciphertext length must be at least 16 bytes (AES-GCM tag), and maximum must not exceed `chunkSize + 16`.

2. **Unbounded Argon2 Parameters (Resource Exhaustion / DoS)**:
   In `AndroidExportManager.verifyOrImportInternal()`, `mem`, `iters`, and `par` are extracted directly from the unauthenticated 106-byte file header:
   ```kotlin
   val mem = buf.int
   val iters = buf.int
   val par = buf.get().toInt()
   val kek = generateKek(passphrase, salt, mem, iters, par)
   ```
   No upper bounds are verified before Argon2id derivation begins. A maliciously crafted header with e.g. `mem = 2 GB` or `iters = 1,000,000` causes an immediate OutOfMemoryError or freezes the CPU in a DoS attack.

3. **Dynamic SQL Injection via Unvalidated Table and Column Names**:
   In `verifyOrImportInternal()`:
   ```kotlin
   val cols = data.keys.joinToString(",") { "\"$it\"" }
   val placeholders = data.keys.joinToString(",") { "?" }
   db?.execSQL("INSERT INTO $type ($cols) VALUES ($placeholders)", vals)
   ```
   Neither `type` (the table name) nor `data.keys` (the column names) are validated against a whitelist or the active SQLite schema. A file containing `"t": "sqlite_master"` or columns with SQL injection strings can execute arbitrary DDL or fail unpredictably.

4. **Hardcoded Live Database Name**:
   During the database swap upon successful import:
   ```kotlin
   val originalFile = context.getDatabasePath("mine_encrypted.db")
   val tempFile = context.getDatabasePath(tempDbName)
   tempFile.copyTo(originalFile, overwrite = true)
   ```
   The production database name `"mine_encrypted.db"` is hardcoded. Tests running against a test database (e.g. `"mine_export_test.db"`) would inadvertently overwrite the live user database upon import.

5. **Missing Post-Import Alarm Reconciliation**:
   When a database is replaced via import, the `reminder` table changes completely, but OS alarms registered in `AlarmManager` are not synchronized. Alarms from the previous database remain armed, and alarms from the imported database are never armed. `AlarmReconciler.reconcile(force = true)` must be called post-swap.

6. **Storage Handle Invalidation**:
   The active `SupportSQLiteOpenHelper` is closed during the file swap (`dbHelper.close()`). The caller must be informed that the app's `Storage` and `OpenHelper` must be reopened.

## 2. Requirements & Specification

1. **Chunk Length Bounds**:
   In `ChunkedAesInputStream`:
   - Accept `chunkSize: Int = 1024 * 1024`.
   - Before allocating `ByteArray(len)`:
     ```kotlin
     if (len < 16 || len > chunkSize + 16) {
         throw SecurityException("Invalid chunk length: $len (expected 16..${chunkSize + 16})")
     }
     ```
2. **KDF Parameter Bounds**:
   In `verifyOrImportInternal`:
   - Read `mem`, `iters`, `par`.
   - Verify:
     - `mem in 1..131072` (up to 128 MB RAM)
     - `iters in 1..10`
     - `par in 1..4`
   - If outside bounds, immediately throw `SecurityException`.
   - Validate header `chunkSize` (must be `1024..16777216`).

3. **Table & Column Whitelisting**:
   - Table whitelist: `setOf("raw_message", "raw_event", "node", "edge", "soul_fact", "app_meta", "day_rule", "reminder", "proposal", "quote_slot")`.
   - Table name `$type` MUST be in `EXPORTED_TABLES`, else throw `SecurityException`.
   - Column whitelist: For each table in `EXPORTED_TABLES`, query `PRAGMA table_info("$table")` on the newly initialized temp database to extract the legitimate column set.
   - For every key in `data.keys`, assert `key in validColumns`, else throw `SecurityException`.
   - Enclose table name and column names in double quotes in the prepared SQL statement.

4. **Configurable Live Database Name**:
   - `AndroidExportManager` constructor parameter: `liveDbName: String = "mine_encrypted.db"`.
   - Swap logic copies `tempFile` to `context.getDatabasePath(liveDbName)` and cleans up WAL/SHM files for `liveDbName`.

5. **Post-Import Reconciliation & Storage Reinitialization**:
   - Provide optional parameter `reconciler: AlarmReconciler? = null` or `scheduler: AlarmScheduler? = null`.
   - After successful swap:
     If `scheduler != null`: open a temporary helper for `liveDbName`, construct `AndroidStorage`, run `AlarmReconciler(storage, scheduler, clock).reconcile(force = true)`, and close the helper.
     If `reconciler != null`: call `reconciler.reconcile(force = true)`.
   - Document clearly in KDoc that caller must reinitialize storage in `MineApp` / `ViewModel`.

## 4. Implementation Details

1. **Chunk Framing Security Validation**:
   In `ChunkedAesInputStream`:
   - Enforced validation check before allocating memory:
     ```kotlin
     val len = ByteBuffer.wrap(lenBuf).int
     if (len < 16 || len > chunkSize + 16) {
         throw SecurityException("Invalid chunk length: $len (expected 16..${chunkSize + 16})")
     }
     val cipherBuf = ByteArray(len)
     ```
   - Throws `SecurityException` instead of `NegativeArraySizeException` or `OutOfMemoryError`.

2. **Argon2id KDF Parameter Bounds**:
   In `verifyOrImportInternal()`:
   - Header limits:
     ```kotlin
     if (mem <= 0 || mem > 131072 || iters !in 1..10 || par !in 1..4) {
         throw SecurityException("KDF parameters out of safe bounds: mem=$mem, iters=$iters, par=$par")
     }
     if (chunkSize !in 1024..(16 * 1024 * 1024)) {
         throw SecurityException("Invalid chunkSize in header: $chunkSize")
     }
     ```

3. **Schema Whitelist & Dynamic Column Verification**:
   - `EXPORTED_TABLES = setOf("raw_message", "raw_event", "node", "edge", "soul_fact", "app_meta", "day_rule", "reminder", "proposal", "quote_slot")`.
   - Any unknown table type in backup stream throws `SecurityException("Disallowed or unknown table in export: $type")`.
   - Valid columns extracted dynamically from fresh SQLite temp database via `PRAGMA table_info("$tName")`.
   - Any key in data not in `validColumns` throws `SecurityException("Disallowed or unknown column '$colKey' for table '$type'")`.
   - SQL identifiers escaped with double quotes: `INSERT INTO "$type" ($cols) VALUES ($placeholders)`.

4. **Configurable Live Database Name**:
   - Added `liveDbName: String = "mine_encrypted.db"` to constructor.
   - Database swap targets `context.getDatabasePath(liveDbName)` and cleans up WAL/SHM files for `liveDbName`.
   - Isolated tests safely run against temporary live databases without modifying production user databases.

5. **Post-Import Alarm Reconciliation**:
   - Added optional `reconciler: AlarmReconciler?` and `scheduler: AlarmScheduler?` constructor parameters.
   - Post-swap invokes `reconciler.reconcile(force = true)` or opens helper on `liveDbName` to reconcile alarms, ensuring imported reminders are armed in `AlarmManager` and stale OS alarms are disarmed.
