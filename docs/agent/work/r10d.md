# Branching Analysis: Task R10d (getStaleNodes Required Injected now Parameter)

Date: 2026-11-04  
Status: In Progress  
Authors: Antigravity  

---

### 1. Goal and Invariant Restatement
- **Goal**:
  Per `session1-remediation-spec.md` line 310:
  > "d. getStaleNodes default now = System.currentTimeMillis() violates the injected-clock rule: make now required."
  Ensure that `Storage.getStaleNodes` strictly requires an injected `now: Long` timestamp, eliminating any fallback to `System.currentTimeMillis()`.
- **Invariant**:
  All time resolution in `Storage` queries must be deterministic and caller-supplied via injected clock abstractions (`clock.now()`). No core query may read system wall clock time directly. Parameter ordering must be consistent across temporal storage APIs (`now: Long` first, `cutoffMs: Long = 30L * 24 * 3600 * 1000L` second).

---

### 2. Hypotheses / Approaches
1. **Hypothesis A (Keep `cutoffMs` first, `now` second without default)**:
   - *Signature*: `suspend fun getStaleNodes(cutoffMs: Long = ..., now: Long): List<Node>`
   - *Issue*: In Kotlin, placing a parameter with a default value before a parameter without a default forces callers who want default cutoff to use named argument syntax `storage.getStaleNodes(now = clock.now())`. This is inconsistent with `getActiveNodeCounts(now: Long, staleCutoffMs: Long = ...)` and `getRankedCandidates(now: Long, staleCutoffMs: Long, perTierLimit: Int = 25)`.
   - *Kill Condition*: Inconsistency with sister methods and poor Kotlin API ergonomics.

2. **Hypothesis B (Reorder parameters: `now: Long` first, `cutoffMs: Long = 30L * 24 * 3600 * 1000L` second)** (CHOSEN):
   - *Signature*: `suspend fun getStaleNodes(now: Long, cutoffMs: Long = 30L * 24 * 3600 * 1000L): List<Node>`
   - *Prediction*: `now` is strictly required without any default. Callers can naturally invoke `storage.getStaleNodes(clock.now())` using the default 30-day cutoff, or `storage.getStaleNodes(clock.now(), customCutoff)`. Matches the exact signature pattern of `getActiveNodeCounts(now: Long, staleCutoffMs: Long = ...)`.
   - *Cheapest Check*: Verify compilation and ergonomics across `ChatController`, `AndroidStorage`, `SharedFakeStorage`, and all test call sites.

3. **Hypothesis C (Overloaded functions: `getStaleNodes(now)` and `getStaleNodes(now, cutoffMs)`)**:
   - *Signature*: Two separate interface methods.
   - *Prediction*: Unnecessary interface bloat when Kotlin interface default parameter on `cutoffMs` natively handles both single-arg and two-arg calls.
   - *Kill Condition*: Premature abstraction / unnecessary method duplication.

4. **Hypothesis D (Inject Clock into Storage rather than passing `now`)**:
   - *Prediction*: `Storage` interface is a pure data persistence abstraction. In Android, `AndroidStorage` does not own business clock state; injecting `now: Long` per query keeps queries pure, deterministic, and easily testable with arbitrary timestamps.
   - *Kill Condition*: Violates existing `Storage` design pattern where `now: Long` is supplied by `ContextBuilder`, `ChatController`, and `Gateway` using their injected `Clock`.

---

### 3. Comprehensive Dimensional Analysis
- **Schema & Migration**: No database schema change. Table structure remains untouched.
- **Concurrency & Lifecycle**: Safe. Passing `now: Long` is purely thread-local and coroutine-safe.
- **Process Death & Reboot**: Independent of process lifecycle; timestamps are supplied from caller clock.
- **Failure Paths**: Missing or invalid `now` is impossible at compile time since `now: Long` is required.
- **Model Behaviour**: LLM does not interact directly with `getStaleNodes`; results populate `UiState.staleItems` and `UiState.inboxCount`.
- **Privacy & Security**: Timestamps contain no personal data.
- **Testability**: Dramatically improved. All tests can step time forward or backward deterministically using `FakeClock` without reliance on `System.currentTimeMillis()`.
- **Blast Radius**: `Storage.kt`, `AndroidStorage.kt`, `SharedFakeStorage.kt`, `ChatController.kt`, and test call sites in `ContextBuilderTest.kt`, `AndroidStorageTest.kt`, `DatabaseMigrationTest.kt`. Also audit and fix any stray `System.currentTimeMillis()` in `SharedFakeStorage.deleteEdge`.

---

### 4. Pre-Mortem (3 Potential Failure Modes)
1. *Call sites passing positional arguments inverted*: If a caller passed `(cutoff, now)` without argument names, swapping to `(now, cutoff)` could interpret `cutoff` (e.g. 30 days) as timestamp ~1970 and return empty.
   - *Prevention*: Inspect every call site in `app` and `core` and verify parameter assignments.
2. *Default value lost in interface inheritance*: If `Storage.kt` defines default `cutoffMs` but an implementing class defines a different default, compilation or runtime divergence could occur.
   - *Prevention*: Put default value `cutoffMs: Long = 30L * 24 * 3600 * 1000L` strictly on `Storage.kt` interface; omit default on overrides.
3. *Stray wall-clock calls in storage helper functions*: Other storage methods in `SharedFakeStorage` might use `System.currentTimeMillis()`.
   - *Prevention*: Fix `SharedFakeStorage.deleteEdge` to use `clock.now()` instead of `System.currentTimeMillis()`.
