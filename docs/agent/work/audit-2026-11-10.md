## 2. New Defects with Proof

The audit uncovered **14 critical and high-severity defects** across storage, concurrency, and UI layers:

### Defect 1: Outbox `deadline_at` String Corruption [CRITICAL]
- **File & Line:** [`AndroidStorage.kt#L1280-L1285`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/app/src/main/java/com/anchor/mine/storage/AndroidStorage.kt#L1280-L1285)
- **Proof:**
  ```kotlin
  dbHelper.writableDatabase.execSQL(
      "INSERT OR IGNORE INTO outbox (...) VALUES (?,?,?,?,?,?,?,?,?,?,?,?)",
      arrayOf<Any>(
          job.id, job.jobType, job.priority, job.payloadJson, job.idemKey, job.status, job.attempts,
          job.nextTryAt, job.deadlineAt ?: "", job.createdAt, job.updatedAt, job.lastError ?: ""
      )
  )
  ```
  `deadline_at` is an INTEGER column in SQLite. Because `arrayOf<Any>` is used rather than `arrayOf<Any?>`, `job.deadlineAt ?: ""` writes an empty string `""` into SQLite instead of `NULL`. In `c.toOutboxJob()` ([`AndroidStorage.kt#L1350`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/app/src/main/java/com/anchor/mine/storage/AndroidStorage.kt#L1350)), `isNull(8)` returns `false`, and `cursor.getLong(8)` on `""` returns `0L`.
- **Impact:** Any job enqueued with `deadlineAt = null` is read back as `deadlineAt = 0L` (Jan 1, 1970). When `dropStaleOutbox(now)` runs, **every null-deadline job is immediately dropped as expired**, silently destroying background work!

### Defect 2: UI Bricking on Benign Background / Action Errors [CRITICAL]
- **File & Line:** [`ChatController.kt:275, 523, 682, 692, 710, 720, 729, 746, 755, 764, 773`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/core/src/main/java/com/anchor/core/ui/ChatController.kt#L275) & [`MainActivity.kt:222-245`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/app/src/main/java/com/anchor/mine/MainActivity.kt#L222-L245)

- **Impact:** An ordinary I/O hiccup during a background proactive check or memory viewer refresh sets `globalError`, which replaces the entire app with a permanent "Fatal Error" screen with no dismiss button, bricking the app until the user force-stops it!

### Defect 3: Missing Exception Boundaries in 12+ UI Actions [CRITICAL]
- **File & Line:** [`ChatController.kt#L339-L500, L526-L557`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/core/src/main/java/com/anchor/core/ui/ChatController.kt#L339-L500)

### Defect 4: Composer Live Send Dropped on Network Cut [CRITICAL]
- **File & Line:** [`ChatController.kt#L1252-L1259`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/core/src/main/java/com/anchor/core/ui/ChatController.kt#L1252-L1259)

  if (!queuedBatch && e is OfflineException && existingUserMsgId != null) {

  When a user sends a message via the composer in `MainActivity`, `existingUserMsgId` is `null`. If the network cuts out or transport throws an `OfflineException` mid-send, `existingUserMsgId != null` evaluates to `false`.
- **Impact:** The message is never enqueued into `outbox`! It displays a transient connection error, but on reconnect it is permanently lost from the drain queue.

### Defect 5: Inverted Chronological Search Drops Stored Quick Captures [CRITICAL]
- **File & Line:** [`QuickCapture.kt#L94-L98, L106-L111`](file:///C:/Users/Banespire/AndroidStudioProjects/Mine/core/src/main/java/com/anchor/core/capture/QuickCapture.kt#L94-L98)
- **Proof:**
  `storage.getRecentMessages(200)` returns messages ordered `ts_utc DESC, rowid DESC` (newest first).
  `hasAssistantAfter(recent, index)` checks `recent.drop(index + 1)`.
  In a descending list, dropping items after index `i` yields **older** messages, not newer ones!
- **Impact:** If there is any assistant message in the last 200 messages anywhere in history, `hasAssistantAfter` evaluates `true` for every capture. Consequently, `QuickCapture.pending(storage)` returns `emptyList()`. Quick captures saved while the app was closed are **never sent upon restart and stay abandoned forever**!

## 4. Blueprint Contradictions & Contract Gaps

1. **Release Gate X-07 / Blueprint 40 §3.6 (Persistent 429 Cooldown):**
   - Blueprint 40 mandates that provider 429 cooldowns survive process death.
   - `RateLimiter.kt` currently holds cooldowns in an in-memory `HashMap`. If Android kills the app process, the cooldown is lost, violating Gate X-07. (Draft Decision **D-155**).
2. **Blueprint 24 §3.1 & Blueprint 16 §3.7 (Persona Layering & Tone Safety):**
   - `PersonaEngine.composeSystemPrompt` contains the tone safety distress override.
   - `ChatController.buildJsonPayload` currently hardcodes a static instruction string and omits `personaEngine.composeSystemPrompt`. Distress override is bypassed in live chat. (Draft Decision **D-158**).
3. **Blueprint 50 §3.7 / Decision D-071 (Composer Message Coalescing):**
   - D-071 states: "One live turn at a time. Messages sent meanwhile are coalesced into a single follow-up turn."
   - `ChatController.onAction(UiAction.SendMessage)` drops messages if `isChatLoading == true`. (Draft Decision **D-157**).
4. **Blueprint 41 §2 & §3.2 (Transport Disconnect Normalization):**
   - Mid-stream socket disconnects are caught as generic exceptions rather than normalized to `OfflineException`, preventing outbox enqueueing. (Draft Decision **D-156**).
5. **Blueprint 16 §3.1 (Cleartext HTTP Transport Warning):**
   - `AndroidHttpTransport` accepts cleartext `http://` without verifying localhost/LAN or alerting the user.
