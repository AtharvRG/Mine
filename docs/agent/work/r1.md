# R1 Branching Analysis: Reschedule/Cancel/Complete After Ambiguity

Date: 2026-11-03
Lead Engineer: Antigravity
Decisions: D-110, D-111, D-5

---

## 1. Problem Statement

1. **Broken Confirm Intent Handling**: `Gateway.handleConfirmChange` unconditionally sets `status = if (proposal.intent == IntentType.CANCEL) "cancelled" else "done"`. When a user resolves an ambiguous `RESCHEDULE` proposal by tapping a chip, the node is wrongly marked `done` and its reminder is left armed or unchanged.
2. **Missing Destination Time Payload**: The `proposal` table and `Proposal` model do not preserve the destination time (`due_text` / `targetTimeMillis`) supplied during the initial `propose_change` turn. Thus, `handleConfirmChange` cannot reschedule the item without making a second LLM query or guessing.
3. **Resolver Target Time Pollution**: `Gateway.handleResolveChange` passes `targetTimeMillis` to `Resolver.resolve` for all intents. For `RESCHEDULE`, this time is the *destination*, not the time of the existing item. `Resolver.resolve` gives a +0.5 score bonus and executes a "time override" for nodes due within 24h of `targetTimeMillis`, causing it to select the wrong item as `ClearWinner` instead of recognizing ambiguity. For `CANCEL`/`COMPLETE`, `targetTimeMillis` is a valid identifier (e.g. "cancel tomorrow's dinner") and must be retained.
4. **Unsupported Intents Faking Success**: `UPDATE`, `PAUSE`, and `RESUME` are not supported in v1, yet `UPDATE` executes a no-op timestamp update and reports `Committed("Applied UPDATE")`. Per D-111, these must return an explicit `ToolResult.Error("<INTENT> is not supported yet")` immediately before any DB mutation or proposal creation.
5. **System Prompt Prompting Unsupported Intent**: `ChatController.buildJsonPayload` advertises `UPDATE` in the `propose_change` intent enum, causing models to emit `UPDATE` calls.

## 3. Gateway Branching & Execution Logic

### 3.1 `propose_change`
1. Parse intent.
2. If `intent in listOf(IntentType.UPDATE, IntentType.PAUSE, IntentType.RESUME)`:
   - Return `ToolResult.Error("${intent.name} is not supported yet")` immediately.
3. If `intent == IntentType.CREATE`:
   - Duplicate check -> `handleCreate`.
4. If `intent in listOf(IntentType.CANCEL, IntentType.COMPLETE, IntentType.RESCHEDULE)`:
   - For `RESCHEDULE`, pass `timeForResolver = null`.
   - For `CANCEL`, `COMPLETE`, pass `timeForResolver = targetTimeMillis`.
   - Call `handleResolveChange(intent, hint, timeForResolver, targetTimeMillis)`.

### 3.2 `handleResolveChange`
- When `Resolution.Ambiguous`:
  - If `intent == IntentType.RESCHEDULE`, encode `ProposalPayload(targetAtMillis = destinationTimeMillis)` to JSON.
  - Save `Proposal(pId, "ambiguous", intent, opts, payload = payloadJson)`.
  - Return `ToolResult.Ambiguous(pId, "ask: which item", options)`.
- When `Resolution.ClearWinner`:
  - If `intent == IntentType.RESCHEDULE`:
    - `newNode = oldNode.copy(dueAt = destinationTimeMillis ?: oldNode.dueAt, updatedAt = now)`.
    - Fetch `oldRem = storage.getReminderByNodeId(oldNode.id)`.
    - `newRem = if (destinationTimeMillis != null) Reminder(oldRem?.id ?: "rem_...", newNode.title, destinationTimeMillis, newNode.id, tier = oldRem?.tier ?: AlarmTier.ALARM) else oldRem`.
    - Atomically commit node + event + newRem.

### 3.3 `handleConfirmChange`
1. Fetch proposal by ID. If not found or expired (>24h) -> Error("Proposal not found").
2. If `proposal.status != "open"` -> Error("Proposal already resolved").
3. Find chosen node from `proposal.options`. If not found -> Error("Invalid choice").
4. Fetch node from storage. If null or not active/in_progress -> Error("Node is no longer active").
5. Branch on `proposal.intent`:
   - **`IntentType.CANCEL`**:
     - `newNode = node.copy(status = "cancelled", closedAt = now, updatedAt = now)`.
     - `oldRem = storage.getReminderByNodeId(node.id)`.
     - Commit with `deleteReminderId = oldRem?.id`, `consumeProposalId = proposalId`.
     - Return `Committed("CANCEL", newNode.id, "Applied CANCEL: ${newNode.title}", uId)`.
   - **`IntentType.COMPLETE`**:
     - `newNode = node.copy(status = "done", closedAt = now, updatedAt = now)`.
     - `oldRem = storage.getReminderByNodeId(node.id)`.
     - Commit with `deleteReminderId = oldRem?.id`, `consumeProposalId = proposalId`.
     - Return `Committed("COMPLETE", newNode.id, "Applied COMPLETE: ${newNode.title}", uId)`.
   - **`IntentType.RESCHEDULE`**:
     - Decode `proposal.payload` into `ProposalPayload`.
     - Validate destination time:
       - `val target = payload?.targetAtMillis`
       - If `target == null || target <= clock.now()`:
         - Consume proposal immediately: `storage.consumeProposal(proposalId)`.
         - Return `ToolResult.Error("That time has already passed; tell me the new time again")`.
     - Valid target:
       - `newNode = node.copy(dueAt = target, updatedAt = now)` (status remains same, e.g. "active", `closedAt = null`).
       - `oldRem = storage.getReminderByNodeId(node.id)`.
       - `newRem = if (oldRem != null) oldRem.copy(text = newNode.title, fireAtMillis = target) else Reminder("r_${node.id}", newNode.title, target, node.id, tier = AlarmTier.ALARM)`.
       - Commit: `updateNodeAndCommit(newNode, event, deleteReminderId = null, upsertReminder = newRem, consumeProposalId = proposalId)`.
       - `beforeJson = json.encodeToString(NodeStateSnapshot(node, oldRem))`
       - `afterJson = json.encodeToString(NodeStateSnapshot(newNode, newRem))`
       - Receipt text: `"Rescheduled: ${newNode.title} to ${dateResolver.format(target)}"`.
   - **Any other intent**:
     - Return `ToolResult.Error("${proposal.intent.name} is not supported yet")`.

## 4. Test Strategy (TDD: Fail First)

We construct targeted unit tests in `:core:test` before modifying implementation:
1. `testRescheduleAmbiguity_ConfirmAndUndo`:
   - 2 dinner nodes with distinct dates.
   - Propose reschedule to tomorrow 8pm -> Ambiguous.
   - Confirm chip -> chosen node dueAt updated, status remains active, reminder moved with same tier, proposal consumed, receipt has undo token.
   - Undo -> node dueAt restored, reminder restored.
2. `testResolver_RescheduleNullTime_vs_CancelTargetTime`:
   - 2 nodes: "dinner" tomorrow 19:00, "dinner" Thursday.
   - `RESCHEDULE` with destination "tomorrow 8pm" -> Ambiguous (not ClearWinner).
   - `CANCEL` with hint "tomorrow's dinner" and time tomorrow 19:00 -> ClearWinner tomorrow.
3. `testRescheduleAmbiguity_TargetInPast_ConsumesProposalAndErrors`:
   - Proposal payload has target time in the past (relative to `clock.now()`).
   - Confirm chip -> returns `Error` containing "passed", proposal status marked "consumed".
4. `testUpdateDirectAndProposal_ReturnsExplicitError`:
   - `propose_change` with `UPDATE` returns Error "UPDATE is not supported yet".
   - Proposal confirmed with `UPDATE` intent returns Error "UPDATE is not supported yet", node untouched, no event logged.
5. `testChatController_ConfirmChange_ZeroModelCalls`:
   - End-to-end ChatController action `ConfirmProposal`.
   - Assert transport call count is 0.
