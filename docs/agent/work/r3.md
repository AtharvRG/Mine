# Task R3: Alarm Truth, Permissions, and Silent Failures

Date: 2026-11-03
Status: Completed
Author: Antigravity / OpenClaude

---

## 1. Context & Objectives

Reminders are the core promise of the Mine application. Android 12+ (API 31+) and OEM battery optimizations aggressively throttle background alarms. Task R3 enforces strict platform compliance, eliminates permission bloat, stops silent failures, extracts a unified core `AlarmReconciler`, distinguishes swept missed reminders, and repairs the alarm self-test.

### Key Architectural Anchors
- **D-100**: Node is the truth; Reminder is the alarm attached by `node_id`. Arm only after commit.
- **D-102**: Manifest must declare **none** of: `VIBRATE`, `WAKE_LOCK`, `USE_EXACT_ALARM`, `SCHEDULE_EXACT_ALARM`. `AlarmManager.setAlarmClock()` requires none of these, wakes the device from Doze, and displays the system status-bar alarm clock icon. `GENTLE` reminders use `setAndAllowWhileIdle()` which is inexact.
- **D-105**: Status-bar icon disclosure. Gentle tier notification without alarm clock.
- **Blueprint 30 & 42**: Layered arming, honest reliability state, zero silent failures (Rule 2).

## 2. Problems Identified

1. **Manifest Permission Contradiction (D-102)**:
   - `app/src/main/AndroidManifest.xml` still declares `<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM" />`.
   - `setAlarmClock` does not require `SCHEDULE_EXACT_ALARM`. Declaring it creates unnecessary user prompts, Play Store policy scrutiny, and violates D-102.

2. **Silent Failure Swallowing in Scheduler (Rule 2 Violation)**:
   - In `AndroidAlarmScheduler.kt`, when scheduling fails or throws `SecurityException`, it catches it and silently falls back to `setAndAllowWhileIdle`, concealing failure from caller, user, and diagnostics.
   - `AlarmScheduler.schedule()` returns `Unit`, giving no indication whether the alarm was actually armed.

3. **Duplicated and Wasteful Reconciliation**:
   - `ChatController.reconcileAlarms` and `BootReceiver.kt` duplicate alarm reconciliation code.
   - `ChatController.refreshUI()` blindly re-arms **every single pending reminder** on every single UI refresh/turn, regardless of whether fire time changed.
   - Existing tests like `testReconcileAlarms_UpdatesTime_And_CancelsOrphans` only pass because of this brute-force re-arming, failing to verify selective reconciliation.

4. **Undifferentiated Missed Alarms**:
   - When `BootReceiver` runs the sweeper for missed alarms, it passes `EXTRA_TEXT = "Missed: ..."`, but `AlarmReceiver` queries the database for `rem.text` and overwrites it. Missed reminders look identical to on-time reminders.

5. **Broken AlarmSelfTest**:
   - `AlarmSelfTest.kt` returns early if `!alarmManager.canScheduleExactAlarms()`, skipping tests on Android 14+.
   - Missing verification that `ALARM` tier sets `alarmManager.nextAlarmClock` (`triggerTime == fireAt`, `showIntent.creatorPackage == packageName`), and that `GENTLE` tier does **not** register in `nextAlarmClock`.

## 3. Detailed Technical Design

### A. Manifest Permissions
- Remove `SCHEDULE_EXACT_ALARM` from `app/src/main/AndroidManifest.xml`.
- Add test in `app/src/androidTest/java/com/anchor/mine/alarms/ManifestPermissionTest.kt` asserting that the merged package manifest declares none of:
  - `android.permission.VIBRATE`
  - `android.permission.WAKE_LOCK`
  - `android.permission.USE_EXACT_ALARM`
  - `android.permission.SCHEDULE_EXACT_ALARM`

### B. Explicit Schedule Result & Reliability Tracking
- Define in `core/src/main/java/com/anchor/core/alarms/AlarmScheduler.kt`:
  ```kotlin
  sealed class ScheduleResult {
      data object Armed : ScheduleResult()
      data class Failed(val reason: String) : ScheduleResult()
  }
  ```
- Change `AlarmScheduler.schedule(reminder: Reminder): ScheduleResult`.
- Update `ReliabilityState` in `core/src/main/java/com/anchor/core/models/Stats.kt` to include `val issuesJson: String? = null`.
- Update `AndroidStorage.kt` and `SharedFakeStorage.kt` to persist and load `issues_json` in table `reliability_state`.
- Update `UiState` in `core/src/main/java/com/anchor/core/ui/ChatContract.kt` to include `val schedulingError: String? = null`.
- In `AndroidAlarmScheduler.kt`:
  - When scheduling `ALARM` tier, invoke `alarmManager.setAlarmClock(...)`.
  - When scheduling `GENTLE` tier, invoke `alarmManager.setAndAllowWhileIdle(...)`.
  - Wrap in a try-catch returning `ScheduleResult.Failed(e.message ?: e.javaClass.simpleName)` on any exception. Never swallow or silently fall back.
  - Return `ScheduleResult.Armed` on success.

### C. Unified Core `AlarmReconciler`
- Create `core/src/main/java/com/anchor/core/alarms/AlarmReconciler.kt`:
  ```kotlin
  class AlarmReconciler(
      private val storage: Storage,
      private val scheduler: AlarmScheduler,
      private val clock: Clock
  ) {
      suspend fun reconcile(force: Boolean): List<ScheduleResult>
  }
  ```
- **Reconciliation Algorithm**:
  1. Fetch `pending = storage.getPendingReminders()` and `registered = storage.getRegisteredAlarms()`.
  2. Compute orphans: registered IDs not present in pending. Cancel via `scheduler.cancel(id)` and remove via `storage.deleteRegisteredAlarm(id)`.
  3. When `force == true` (app startup, boot, time/timezone change, post-import):
     - For each reminder in `pending` where `fireAtMillis >= now - 60000L`:
       - Invoke `val result = scheduler.schedule(r)`.
       - If `result is ScheduleResult.Armed`, record `storage.saveRegisteredAlarm(r.id, r.id.hashCode(), r.fireAtMillis)`.
       - If `result is ScheduleResult.Failed`, record reliability score `"at_risk"` with issue details.
  4. When `force == false` (post-commit, UI refresh):
     - For each reminder in `pending` where `fireAtMillis >= now - 60000L`:
       - If `registeredMap[r.id] != r.fireAtMillis`:
         - Invoke `scheduler.schedule(r)`.
         - Update registered alarm on Armed.
         - Record reliability issue on Failed.
       - If registered fire time equals `r.fireAtMillis`:
         - **Do nothing** (skip scheduling, avoid unnecessary OS alarm churning).
  5. If any failure occurs, return the list of failures so callers (`ChatController`) can update `UiState.schedulingError`.
- Deduplicate: Replace private `ChatController.reconcileAlarms` and `BootReceiver` logic with `AlarmReconciler`.
  - `ChatController.init`: `alarmReconciler.reconcile(force = true)`
  - `ChatController.refreshUI`: `alarmReconciler.reconcile(force = false)`
  - `BootReceiver`: `alarmReconciler.reconcile(force = true)`

### D. Missed Alarm Indication
- `AlarmReceiver.kt`:
  - Inspect `intent.getBooleanExtra("EXTRA_MISSED", false)`.
  - If true, prefix notification text: `"Missed: $safeText"`.
- `BootReceiver.kt`:
  - When forwarding sweeper missed alarms, pass `intent.putExtra("EXTRA_MISSED", true)`.

### E. AlarmSelfTest & nextAlarmClock Verification
- In `app/src/androidTest/java/com/anchor/mine/alarms/AlarmSelfTest.kt`:
  - Remove early return on `canScheduleExactAlarms()`.
  - Schedule `ALARM` tier reminder 5s out, assert `AlarmReceiver.lastFiredId`.
  - Verify `alarmManager.nextAlarmClock`:
    - `triggerTime == fireAt`
    - `showIntent.creatorPackage == context.packageName`
  - Schedule `GENTLE` tier reminder, assert it does **not** register in `alarmManager.nextAlarmClock`.
