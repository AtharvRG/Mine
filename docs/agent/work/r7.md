# Task R7: Receipts from Operation Log (T6)

Date: 2026-11-04  
Status: Completed  
Author: Antigravity / OpenClaude  

---

## 1. Problem Statement

Previously, receipts lived purely in memory inside `UiState.receipts` and `ChatController`:
1. **Lost on Process Death**: When the application process was killed or `ChatController` was recreated, all receipts and undo tokens were lost, preventing users from undoing operations performed earlier in the 24-hour window.
2. **Never Expire**: In-memory undo tokens did not expire after 24 hours while the session remained alive.
3. **No Message Linkage**: Receipts lacked linkage to the causing user message (`causeMsgId = null`), rendering them in an undifferentiated block at the bottom of the chat list rather than anchored under the relevant prompt.
4. **Model Prose & Generic Text**: Receipts relied on transient strings returned from tool executions rather than deterministic formatting derived from the audited, immutable `raw_event` log.
5. **Undone State Not Surfaced**: When an action was undone, the original receipt in memory retained its undo button unless manually modified, risking redundant or invalid undo invocations.

## 2. Requirements & Specification

From `docs/agent/work/session1-remediation-spec.md` (Task R7):
1. **RawEvent causeMsgId**:
   - `RawEvent` model in `ToolContracts.kt` carries `val causeMsgId: String? = null`.
   - All `raw_event` inserts in `AndroidStorage` and `SharedFakeStorage` write `event.causeMsgId` to the existing `cause_msg_id` column.
   - `ChatController` passes `userMsgId` into `gateway.executeTool(..., causeMsgId = userMsgId)`.
   - Chip, undo, and stale actions explicitly pass `causeMsgId = null`.
2. **Deterministic ReceiptFormatter**:
   - Core `ReceiptFormatter` transforms a `RawEvent` (`op_type`, `before_json`, `after_json`) into a deterministic receipt line in the device's configured time format (via `DateResolver`), e.g.:
     - `CREATE`: `"Created: <Title> (<device-formatted date-time>)"` (or `"Created: <Title>"` if undated)
     - `CANCEL`: `"Cancelled: <Title> (<device-formatted date-time>)"` (or `"Cancelled: <Title>"` if undated)
     - `COMPLETE`: `"Completed: <Title> (<device-formatted date-time>)"` (or `"Completed: <Title>"` if undated)
     - `RESCHEDULE`: `"Rescheduled: <Title> to <device-formatted date-time>"`
     - `KEEP_STALE`: `"Kept: <Title>"`
     - `CANCEL_STALE`: `"Cancelled: <Title>"`
     - `SCHEDULE`: `"Scheduled reminder: <Text> (<device-formatted date-time>)"`
     - `DELETE`: `"Cancelled reminder: <Text>"`
     - `CONFIRM`/`ACCEPT`: `"Saved to Soul: <Statement>"`
     - `REJECT`: `"Dismissed Soul fact"`
     - `LINK`: `"Linked follow-up"`
     - `UNLINK`: `"Removed follow-up link"`
   - Never uses model prose.
3. **Storage.getRecentEvents(limit)**:
   - Queries UI-visible operation types (`CREATE`, `CANCEL`, `COMPLETE`, `RESCHEDULE`, `SCHEDULE`, `KEEP_STALE`, `CANCEL_STALE`, `DELETE`, `CONFIRM`, `ACCEPT`, `REJECT`, `LINK`, `UNLINK`) where `undo_of IS NULL`, ordered chronologically (`ts_utc ASC` among the most recent `limit` records).
4. **UiState.receipts Construction**:
   - `UiState.receipts` is reconstructed dynamically from `Storage.getRecentEvents(limit)`.
   - `undoValid = (clock.now() - event.tsUtc < 24 * 3600 * 1000L) && !storage.hasUndo(event.opId)`.
   - `undoToken = if (undoValid) event.opId else null`.
   - Receipts retain `causeMsgId` so the UI can anchor them directly under the causing message.
5. **Test Scenarios**:
   - Recreating the controller restores receipts and valid undo tokens from storage.
   - After 24 hours, `undoToken` is absent (`null`).
   - Undone receipts show no undo token (`hasUndo -> undoToken == null`).
   - Receipt ordering and `causeMsgId` are preserved.
   - Receipts contain no model prose.

## 3. Implementation Details

1. **Domain Models**:
   - `RawEvent` in `ToolContracts.kt` updated with `@SerialName("cause_msg_id") val causeMsgId: String? = null`.
   - `ReceiptState` in `ChatContract.kt` updated with `val causeMsgId: String? = null, val timestamp: Long = 0L`.
2. **Deterministic ReceiptFormatter**:
   - Implemented `ReceiptFormatter` in `com.anchor.core.ui.ReceiptFormatter.kt`.
   - Accurately parses `beforeJson` and `afterJson` snapshots for nodes, reminders, and soul facts. Formats dates using injected `DateResolver` to strictly reflect 12h/24h user preferences.
3. **Storage Interface & Implementation**:
   - Added `suspend fun getRecentEvents(limit: Int): List<RawEvent>` to `Storage.kt`.
   - Implemented `getRecentEvents` in `AndroidStorage.kt` using SQL query filtering UI-visible op types and `undo_of IS NULL` ordered chronologically (`ts_utc ASC`).
   - Implemented in `SharedFakeStorage.kt`.
   - Updated all `INSERT INTO raw_event` call sites across `AndroidStorage` (`createNodeAndCommit`, `updateNodeAndCommit`, `undoChangeAndCommit`, `createEdgeAndCommit`, `deleteEdgeAndCommit`, `confirmSoulFactAndCommit`, `rejectSoulFactAndCommit`) to store `cause_msg_id`.
   - Updated `getEvent(opId)` to read `cause_msg_id`.
4. **Gateway & ChatController**:
   - Added `causeMsgId: String? = null` parameter to `Gateway.executeTool(...)` and plumbed through `handleCreate`, `handleCancel`, `handleComplete`, `handleReschedule`, `handleCreateEdge`, `handleDeleteEdge`.
   - In `ChatController`, captured user message ID `userMsgId` during `SendMessage` and passed into `gateway.executeTool(call, executedCalls, messageText, causeMsgId = userMsgId)`.
   - Replaced ephemeral receipts in `ChatController` with `loadReceipts()` querying `storage.getRecentEvents(30)` on `refreshUI()` and startup.
   - In `UiAction.Undo`, attached `undoToken = null` to prevent nested undo loops.

     - `testAfter24Hours_UndoTokenIsAbsent`: PASSED

     - `testReceiptOrderAndCauseMsgIdCorrect`: PASSED
     - `testNoModelTextInReceipts`: PASSED
     - `testReceiptFormatter_AllUiVisibleOpTypes`: PASSED
