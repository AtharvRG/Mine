# Task R6: Gentle Tier is a Dead End (T-C)

Date: 2026-11-04  
Status: Complete  
Author: Antigravity / OpenClaude  

---

## 1. Problem Statement

In the previous codebase state, the Gentle reminder tier (Decision D-105) was functionally unreachable:
1. `propose_change` tool accepted no `tier` argument.
2. `schedule_reminder` had been removed from the system prompt to eliminate duplicate alarm scheduling.
3. As a result, every user-requested reminder defaulted to `AlarmTier.ALARM`.
4. During `RESCHEDULE`, the reminder was reconstructed with the default `tier`, converting any existing `GENTLE` reminders into `ALARM` tier reminders.
5. In ambiguity resolution (`confirm_change`), time-chip proposals (`kind = "time"`) lacked the `tier` parameter in `ProposalPayload`, overwriting the user's intended tier with `AlarmTier.ALARM`.
6. Undoing a reschedule had to be verified to ensure the prior reminder snapshot accurately restored the original tier.

---

## 2. Requirements & Specification

From `docs/agent/work/session1-remediation-spec.md` (Task R6):
1. **Tool Definition & Parameter**:
   `propose_change` must accept an optional `tier="alarm"|"gentle"` parameter. Unrecognized values (e.g. `"super_whisper"`) must safely default to `AlarmTier.ALARM` without crashing or throwing exceptions.
2. **System Prompt Documentation**:
   Document the `tier` parameter in `ChatController.buildJsonPayload`:
   - Tool description: `tier: optional "alarm"|"gentle"`
   - Prompt rule: `"Use tier=\"gentle\" only when the user says low priority, quiet, or no alarm; otherwise default to alarm."`
   - Example added demonstrating gentle tier usage.
3. **Intent Handling**:
   - `CREATE`: honours the requested `tier` and attaches it to the generated `Reminder`.
   - `RESCHEDULE`: preserves the existing reminder's tier (both in direct ClearWinner resolution and in Ambiguous candidate selection).
   - Time-chip proposals (`kind = "time"`): `ProposalPayload` captures `tier`, ensuring zero-model-call chip confirmation commits the reminder with the exact requested tier.
   - `undo`: restoring a node snapshot accurately reinstates the previous `tier`.
